# M1.2 — BotLogic command policy

**M1.2 — PASS.**

Engo can use BotLogic as an optional second policy layer for commands that already have a local `ENGO_COMMAND_PERMISSIONS` requirement.

For a locally authorized, verified IRC account Engo queries:

```prolog
may_execute('account','command').
```

A successful BotLogic query with no solutions denies the command. One or more solutions permits it.

## Authority boundary

BotLogic does not grant Engo permissions.

The existing local account/command permission configuration remains the authority for who is eligible for a protected command. BotLogic is only consulted after that local authorization is present.

If BotLogic is unavailable or the query fails, the policy hook fails open to Engo's existing local authorization result. This preserves the standalone-first requirement: an optional service outage cannot disable ordinary Engo operation.

BotLogic policy denial is therefore an additional restriction, never an elevation of privilege.

## Identity

Policy queries use only Engo's verified IRC account identity. Nicknames are not used as authorization identities.

## Independence

BotAI and PBMP remain independent of this policy path. BotWeb is not involved.
