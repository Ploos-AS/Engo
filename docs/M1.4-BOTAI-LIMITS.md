# M1.4 — AI request limiting

Engo limits optional BotAI traffic independently of IRC processing.

Defaults:

```sh
ENGO_BOTAI_MAX_CONCURRENT=2
ENGO_BOTAI_COOLDOWN=2s
```

`ENGO_BOTAI_MAX_CONCURRENT` bounds in-flight BotAI calls for the IRC session.
`ENGO_BOTAI_COOLDOWN` applies per M1.2 conversation scope, so one busy channel
or private conversation cannot immediately repeat requests while unrelated
scopes remain eligible.

Both `!ai` and M1.3 natural conversation share the same limiter. Explicit
`!ai` calls receive a short busy notice when limited. Natural conversation
drops a limited trigger silently to avoid channel noise.

The limiter never blocks waiting for capacity. BotAI saturation therefore
does not stall the IRC event loop. A provider request that has already acquired
a slot remains bounded by `ENGO_BOTAI_TIMEOUT`.
