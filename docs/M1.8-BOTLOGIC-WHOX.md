# M1.8 — BotLogic WHOX account bootstrap

**M1.8 — PASS.**

Engo now uses an explicit WHOX contract when requesting channel identity state:

```irc
WHO #channel %tcna,152
```

The requested fields are query token, channel, nick and services account. Engo accepts account enrichment only from `354 RPL_WHOSPCRPL` replies whose query token is exactly `152`.

Accepted replies can assert:

- `channel_member(Channel, Nick)`;
- `online(Nick)`;
- `authenticated(Nick, Account)` when the WHOX account field is neither empty, `0`, nor `*`.

A `354` carrying another token is ignored by this state path. This prevents unrelated WHOX queries from being interpreted using Engo's field layout.

Servers without useful WHOX responses still have the existing NAMES and standard-WHO paths available; BotLogic remains optional and fail-open.
