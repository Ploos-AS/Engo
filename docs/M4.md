# M4 — Persistence, timers and HTTP capability

Status: **implementation complete; CI qualification pending**

M4 extends the Tengo runtime with bounded persistent state, lifecycle-aware timers and an opt-in outbound HTTPS capability.

## Persistent state

Scripts have a per-script JSON key/value namespace.

- state is preserved across successful reloads and disable/enable cycles
- keys are validated and values are limited to 64 KiB
- files and directories use restrictive permissions
- writes use unique temporary files followed by atomic rename
- mutations are serialized within the process and with an OS file lock across Engo processes
- concurrent-instance and cross-process regression tests cover lost-update protection

## Timers

Tengo scripts can register one-shot and repeating timers:

- `bot("timer_after", duration, handler_id)`
- `bot("timer_every", duration, handler_id)`
- `bot("timer_cancel", handler_id)`

Timer durations are restricted to 1 second through 30 days and each runtime is limited to 32 active timers. Replacement and cancellation use generation tokens to suppress stale callbacks. Failed reloads retain timers from the active generation; successful reloads stop timers belonging to the replaced generation.

## HTTP capability

Outbound HTTP is disabled unless an allowlist is configured. The current capability supports HTTPS GET with:

- exact hostname allowlisting
- HTTPS and port 443 only
- URL userinfo rejection
- environment proxy bypass disabled
- DNS validation and rejection of empty DNS results
- loopback, private, unspecified, multicast and link-local address blocking
- connection-time address filtering to reduce DNS rebinding/TOCTOU exposure
- redirect validation and a five-redirect limit
- configurable timeout and response-body limit

## Qualification

Regression coverage includes persistence, namespace isolation, size limits, concurrent Store instances, cross-process Store mutations, timer limits/replacement/cancellation, reload rollback, timer lifecycle, persistence across reload/disable-enable, HTTP URL/DNS/redirect policy and response-body limits.
