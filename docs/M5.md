# M5 — IRCv3, capabilities and permissions

Status: **implementation substantially complete; CI qualification pending**

M5 hardens Engo's IRC identity and authorization boundary while keeping the bot usable as a standalone headless service.

## IRCv3

Engo negotiates configured capabilities explicitly through CAP LS 302, CAP REQ, CAP ACK and CAP END. Requested capabilities are required for the connection: missing, rejected, disabled or later removed required capabilities fail closed.

Supported configured capabilities are `account-tag`, `account-notify`, `extended-join` and `server-time`. SASL is negotiated separately when credentials are configured. SASL PLAIN requires TLS unless insecure SASL is explicitly enabled.

Capability parsing normalizes names and handles modifiers, values and multiline LS. Dynamic CAP NEW is not automatically enabled: it is ignored after completed negotiation and rejected while registration negotiation is still in progress.

## Account identity and permissions

Authorization is account-based rather than nick-based. Engo can learn account identity from `account-tag`, `ACCOUNT` and `extended-join`. An account is only verified when bound to message `user@host` provenance. Cached identity is reused only when later messages carry the same provenance. Nick reuse, missing or changed provenance, logout, QUIT and CASEMAPPING changes fail closed.

PART and KICK do not revoke network-level account identity because the user may remain in other channels; provenance is still checked on every later message.

`ENGO_ACCOUNT_PERMISSIONS` grants permissions to authenticated accounts. `ENGO_COMMAND_PERMISSIONS` maps commands to required permissions. Unlisted commands remain public; protected commands are silently denied without a verified account carrying the required permission. Duplicate, malformed and dangling policy entries are rejected at startup.

## Script capabilities

`ENGO_SCRIPT_CAPABILITIES` grants sensitive Tengo APIs per script. HTTP is denied by default and requires the `http` capability as well as the independent global HTTPS hostname allowlist.
